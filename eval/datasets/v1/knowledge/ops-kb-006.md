# order-service 接口超时排查 SOP

## 适用场景
订单服务（order-service）对外接口 P99 延迟超过 1s，或出现大量 `Read timed out`。

## 常见根因
1. 数据库连接池耗尽（见 ERR_5003 手册）。
2. 下游依赖（库存服务、支付服务）抖动，未配置合理超时与熔断。
3. 大促期间 QPS 突增，线程池打满。
4. GC 停顿：Full GC 频繁导致 STW。

## 排查步骤
1. 查看实时指标：QPS、P99、错误率、CPU（Agent 可通过 `query_service_metrics` 工具自动获取）。
2. 确认是否集中在某个接口：结合网关访问日志聚合 top 慢接口。
3. 检查下游依赖的熔断/限流状态，必要时手动降级非核心依赖。
4. 抓取线程 dump，确认线程是否阻塞在数据库或 HTTP 客户端上。

## 处理方案
- 应急：对非核心下游执行降级；扩容 order-service 实例数。
- 治理：为下游调用设置 200ms~1s 超时并启用熔断；优化慢 SQL。
- 复盘：将根因与处理步骤录入故障知识库。

## 相关错误码
- ERR_6001：下游调用超时
- ERR_5003：数据库连接池耗尽（常为上游表现）
