# 服务熔断与限流说明

## 概念
- 熔断：下游错误率/延迟超阈值后自动切断调用，快速失败并走降级逻辑，避免雪崩。
- 限流：对入口流量按容量约束（如令牌桶）放行，超出部分拒绝或排队。

## 策略建议
1. 核心接口优先保可用：限流阈值按压测容量的 80% 设置。
2. 下游依赖按重要性分级：核心依赖重试+熔断，非核心依赖直接降级。
3. 熔断恢复采用半开探测，避免恢复瞬间打挂下游。

## 常见问题
- 熔误伤：阈值过敏感 → 结合历史 P99 动态调整。
- 限流不均：多实例本地限流导致总放行量超标 → 使用 Redis 集中式限流。

## 相关错误码
- ERR_6004：熔断触发
- ERR_6005：请求被限流
